==================================================
PARTICIPANT RULES
==================================================

Both members must understand and follow every rule.


1. TEAM AND ALLOCATION

Teams have exactly two registered members.

No substitution or problem swapping is allowed after allocation.

Teams must work independently and must not exchange code, credentials or private judge feedback.


2. FRESH BUILD ONLY

The Grand Finale solution must be created during the official coding window.

The selection-round prototype, an earlier project, pre-built feature modules or copied solution logic cannot be reused.

Standard frameworks and public libraries are allowed.


3. REPOSITORY AND CODE FREEZE

Create a new repository and share it with the Technical Coordinator at the official start.

Commit regularly with meaningful messages.

Create the final tag before 1:30 PM.

Post-freeze code, data, configuration or deployment changes are not judged.


4. AI USE

AI-assisted and vibe coding are allowed, but teams must understand every component.

Declare all AI tools in the README and final pitch.

Judges may ask either member to explain, modify or debug the solution.


5. PROHIBITED PLATFORMS

Autonomous prompt-to-app and no-code builders, including Lovable, Replit Agent, Emergent and similar platforms, are not allowed.

Inability to explain the submitted work may reduce the technical score or trigger an originality review.


6. DATA AND PRIVACY

Use only supplied, public, consented or realistic sample data.

Do not expose personal identifiers, credentials, medical details, private locations or unverified allegations.

Credit external data, APIs and open-source assets.


7. COACH SAFETY

Keep an offline copy of code and dependencies.

Internet and bus power are not guaranteed.

Screens must remain closed during the ghat section.

Faculty marshal and bus safety instructions override technical work.


==================================================
FINAL SUBMISSION CHECKLIST
==================================================

Complete the final package before the 1:30 PM code freeze.


1. WORKING PROTOTYPE

Runs locally or through a stable deployment using permitted data.


2. SOURCE REPOSITORY

Complete source, dependencies, meaningful commits and final tagged release.


3. README

Problem, setup, architecture, completed features, limitations and tests.


4. ARCHITECTURE DIAGRAM

One-page system/data-flow view with storage, APIs and offline behaviour.


5. DATA STATEMENT

Sources, fields, transformations, limitations and privacy controls.


6. AI-USE DECLARATION

Tools used, purpose, generated components and verification performed.


7. PRESENTATION

Maximum five slides:

- Problem
- Users
- Approach
- Demo
- Impact
- Limitations


8. LIVE DEMONSTRATION

Core user journey plus one failure case or edge case.


9. FEEDBACK RESPONSE

Round 1–3 feedback, changes made and reasons for rejected suggestions.
